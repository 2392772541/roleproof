# RoleProof 产品需求文档（PRD）

- 版本：v0.2 Interview-ready
- 日期：2026-09-07
- 项目性质：个人独立作品
- 定位：中国 AI 产品经理的岗位要求与项目证据工作台

## 1. 用户问题

通用简历生成器会优化语言，却容易产生要求不可追溯、证据不可核验、AI 建议与真实经历混淆三类风险。RoleProof 的首要场景不是批量投递，而是让求职者在选定一个岗位后，形成可讲、可证、可复核的项目材料。

## 2. 核心价值

> 不是替用户写得更像，而是帮助用户证明得更清楚。

每个结论必须能追溯到 Job Source、JD 原文、Requirement 和 Evidence；没有证据时显示 Gap。

## 3. 成功标准

### 已可工程验证

- 无 API Key 可完成岗位录入到面试复盘。
- Match 和 Portfolio 只能引用真实 Evidence ID。
- Reject 后证据不进入评分和作品集；Edit 后使用人工选择的 ID。
- 原始 JD 不被解析结果覆盖。
- 损坏或关系错误的数据导入会被拒绝。
- 桌面与 390×844 移动端可操作且无 console error。

### 尚需真实用户验证

- 用户能否在 30 分钟内完成一个岗位的证据映射。
- 解析分类和证据推荐的人工修改率。
- 面试官是否更容易理解个人贡献和 AI 边界。
- 作品集准备时间是否减少。

没有真实研究前，不写提升百分比。

## 4. 核心对象

`Job`、`Requirement`、`Evidence`、`EvidenceMatch`、`DecisionLog`、`PortfolioSection`、`InterviewRecord`。

## 5. 功能优先级

### P0 可信闭环

保存来源和原文；解析并人工校正；推荐 Evidence；Accept/Edit/Reject 改变状态；下游只用合法 Evidence ID；保存真实回答。

### P1 评测与证据包

固定回归集、可复算指标、Bad Case、GitHub/Demo/PRD/测试/截图、真实性声明。

### P2 用户验证后再做

模型 Adapter、附件 OCR、分享权限、招聘平台连接、跨设备同步。

## 6. AI 边界

Rule Mode 是可解释基线，不冒充大模型。AI 只能提出建议；用户经历、指标、最终作品集与面试回答由用户确认。后续模型输出必须通过结构化 Schema 和 Evidence ID 校验。

## 7. Evaluation

固定集当前包含 4 条合成 JD、12 条人工类型标签和 26 个期望术语。页面实时计算术语覆盖率、分类准确率、原文可追溯和无依据新增，并把错误落到具体 Requirement。

限制：样本少、标签由作者提供、分布不代表真实岗位。下一阶段先扩大真实脱敏样本与标注者一致性，再比较模型版本。

## 8. 非目标

不做批量自动投递；不承诺录用概率；不抓取受限平台；不伪造公司、客户、收入和转化；不让模型静默覆盖人工编辑。
