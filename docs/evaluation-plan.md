# 评估方案

## 1. JD 解析

建立至少 100 条中文 AI 产品岗位要求测试集，标注类型、关键词和是否硬性要求。

- 分类准确率
- 硬性要求召回率
- 重复要求合并准确率

## 2. 证据匹配

每条岗位要求由两名人工判断是否能被指定项目直接证明。

- Top-1 相关率
- 无证据时正确拒绝率
- Evidence ID 合法率（目标 100%）
- 人工接受率、编辑率、驳回率

## 3. 内容生成

- 事实一致性
- 证据引用正确率
- 不支持陈述率
- 不同岗位项目排序差异

## 4. 产品效果

- 完成一份岗位定制作品集所需时间
- 面试准备覆盖的岗位要求比例
- 每次复盘新增或补强的证据数量
- 7 日和 30 日留存

## 5. 当前自动化测试

- JD 能拆成结构化 Requirement。
- 所有匹配引用均为合法 Evidence ID。
- 五项子分之和严格等于总分且不超过 100。
- 没有匹配证据时返回明确缺口，不强行推荐。

## 6. 数据完整性与破坏性操作回归

除模型效果外，产品必须保证用户长期积累的职位、证据和人工内容不会被一次错误导入或重新生成破坏。

- 非法或不完整工作区导入拒绝率：目标 100%。
- 重复 Job、Requirement、Evidence、Decision、Portfolio、Interview ID 检出率：目标 100%。
- 不存在的 Evidence ID 过滤率：目标 100%。
- Reject 后下游引用残留率：目标 0%。
- Edit 后人工证据引用执行率：目标 100%。
- 作品集重新生成导致人工正文丢失率：目标 0%。
- 面试问题重新生成导致回答、薄弱点或行动丢失率：目标 0%。

## 7. 当前自动化回归补充

- Zod 对完整工作区和各 localStorage 分区执行结构校验。
- 合法 JSON 但错误结构的数据会回退到安全演示状态。
- 人工 Reject 会让匹配强度归零并阻止作品集、面试引用。
- 人工 Edit 可以覆盖 Evidence ID，并真实约束评分与下游生成。
- 作品集和面试的再次生成保留人工内容。
- Playwright 同时在桌面端与 390×844 移动端执行。
